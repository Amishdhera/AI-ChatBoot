# Nova — AI Chatbot SaaS App

A production-ready, full-stack AI chatbot application: React + Vite frontend,
Node/Express backend, Firebase Authentication + Firestore for users and chat
history, and a secure server-side AI integration (Google Gemini by default).

**The AI API key is never exposed to the browser.** All AI calls happen on the
Node.js backend; the frontend only ever talks to your own Express API.

## 2. How the pieces fit together

- **Firebase Authentication** (client SDK, in `frontend/src/firebase/config.js`)
  handles register/login/logout/password reset directly from the browser —
  this is how Firebase Auth is designed to be used, and no secret is involved
  (the "web config" is a public identifier, not an API key that grants access).
- After registering, the frontend creates the user's Firestore profile at
  `users/{uid}` directly, allowed only for that user by `firestore.rules`.
- **All conversation and message data** goes through the **Express backend**,
  which verifies the Firebase ID token on every request (`Authorization: Bearer <token>`)
  using the **Firebase Admin SDK**, then reads/writes Firestore scoped strictly
  to `users/{uid}/...` for that authenticated user. A user can never read or
  write another user's data — enforced both by the backend logic and by
  Firestore rules as defense-in-depth.
- **AI responses** are generated by the backend calling Google's Gemini API with a
  key that lives only in `backend/.env`. The frontend never sees this key.

- Node.js 18+

## 4. Firebase setup

1. Create a Firebase project in the console.
2. **Authentication** → Sign-in method → enable **Email/Password**.
3. **Firestore Database** → Create database (production mode).
4. **Project settings → General → Your apps** → add a **Web app** → copy the
   config values into `frontend/.env` (see below).
5. **Project settings → Service accounts** → "Generate new private key" →
   downloads a JSON file. Use its `project_id`, `client_email`, and
   `private_key` fields to fill `backend/.env`.
6. Deploy the security rules in this repo:
   ```bash
   npm install -g firebase-tools
   firebase login
   firebase use --add        # select your project
   firebase deploy --only firestore:rules
   ```

### Firestore data structure

```
users/{userId}
  { name, email, photoURL, createdAt, updatedAt }

users/{userId}/conversations/{conversationId}
  { title, userId, createdAt, updatedAt }

users/{userId}/conversations/{conversationId}/messages/{messageId}
  { role: "user" | "assistant", content, createdAt }
```

## 5. Environment variables

### Where each key goes

| Key | Location | Exposed to browser? |
|---|---|---|
| `AI_API_KEY` (Gemini) | `backend/.env` **only** | ❌ Never |
| `FIREBASE_PROJECT_ID` / `FIREBASE_CLIENT_EMAIL` / `FIREBASE_PRIVATE_KEY` (Admin SDK) | `backend/.env` **only** | ❌ Never |
| `VITE_FIREBASE_*` (public web config) | `frontend/.env` | ✅ Yes — this is expected and safe |
| `VITE_API_BASE_URL` | `frontend/.env` | ✅ Yes — just your backend's URL |

### `backend/.env` (copy from `backend/.env.example`)

```
PORT=5000
NODE_ENV=development
CLIENT_ORIGIN=http://localhost:5173

AI_API_KEY=your_gemini_api_key_here
AI_MODEL=gemini-2.0-flash

FIREBASE_PROJECT_ID=your_firebase_project_id
FIREBASE_CLIENT_EMAIL=your_service_account_email@your_project.iam.gserviceaccount.com
FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
```

### `frontend/.env` (copy from `frontend/.env.example`)

```
VITE_FIREBASE_API_KEY=
VITE_FIREBASE_AUTH_DOMAIN=
VITE_FIREBASE_PROJECT_ID=
VITE_FIREBASE_STORAGE_BUCKET=
VITE_FIREBASE_MESSAGING_SENDER_ID=
VITE_FIREBASE_APP_ID=
VITE_API_BASE_URL=http://localhost:5000/api
```

Both `.env` files are git-ignored; only the `.env.example` templates are committed.

## 6. Installation & development

```bash
# Backend
cd backend
npm install

# Generates backend/.env for you — asks for the path to your downloaded
# Firebase service-account JSON and your Gemini API key, and writes the
# private key in the exact format the backend expects (no manual copy-paste
# formatting mistakes). Skip this and copy .env.example manually if you'd
# rather fill it in by hand.
node setup-env.js

npm run dev                # http://localhost:5000

# Frontend (in a new terminal)
cd frontend
npm install
cp .env.example .env      # fill in your Firebase project's public web config
npm run dev                # http://localhost:5173
```

Open http://localhost:5173, register an account, and start chatting.

## 7. API documentation

All endpoints below (except `/api/health`) require:
```
Authorization: Bearer <firebase-id-token>
```
Requests without a valid token receive **HTTP 401**.

### `POST /api/chat`
```json
// Request
{ "conversationId": "abc123", "message": "Hello" }

// Response
{ "success": true, "message": { "id": "...", "role": "assistant", "content": "Hi there!" } }
```

### `POST /api/chat/stream`
Same request body, but responds with a `text/event-stream` (SSE) of
`event: token` chunks followed by a final `event: done`. Used for the
token-by-token typing experience.

### `POST /api/chat/regenerate`
```json
{ "conversationId": "abc123" }
```
Deletes the last assistant message and generates a new one from the same history.

### `GET /api/conversations`
Returns all conversations for the authenticated user, most recently updated first.

### `POST /api/conversations`
```json
{ "title": "New chat" }
```

### `GET /api/conversations/:id`
Returns the conversation plus its full message list.

### `PUT /api/conversations/:id`
```json
{ "title": "Renamed chat" }
```

### `DELETE /api/conversations/:id`
Deletes the conversation and all of its messages.

### `DELETE /api/conversations/:conversationId/messages/:messageId`
Deletes a single message.

## 8. Features implemented

- Email/password register, login, logout, forgot password (with password
  visibility toggle, client + Firebase validation, loading/success/error states)
- Protected routes (redirect unauthenticated users to `/login`)
- Sidebar: new chat, search, rename, delete, user menu, settings, logout
- Chat: markdown rendering, syntax-highlighted code blocks with copy button,
  copy message, delete message, regenerate response, timestamps,
  scroll-to-bottom, stop generating, streaming typing indicator
- Suggested prompts on the empty-state dashboard
- Settings page: account info, theme, change password, delete account
  (all destructive actions behind a confirmation modal)
- Dark/light theme, persisted to `localStorage`
- Fully responsive: collapsible sidebar drawer on mobile/tablet
- Toast notifications for all error/success states; backend never leaks
  internal error details or API keys to the client

## 9. Production deployment

**Backend** (Render, Railway, Fly.io, or any Node host):
1. Set the same environment variables as `backend/.env` in your host's dashboard.
2. Build/start command: `npm install && npm start`.
3. Set `CLIENT_ORIGIN` to your deployed frontend's URL (comma-separated for multiple).

**Frontend** (Vercel, Netlify, Firebase Hosting):
1. Build command: `npm run build` (outputs to `frontend/dist`).
2. Set the `VITE_*` environment variables in your host's dashboard.
3. Set `VITE_API_BASE_URL` to your deployed backend's URL, e.g. `https://api.yourapp.com/api`.

**Firestore rules**: run `firebase deploy --only firestore:rules` whenever `firestore.rules` changes.

## 10. Security notes

- The AI API key only ever lives in `backend/.env` and is read via
  `process.env` on the server — it is not present anywhere in the frontend
  bundle, Vite env vars, or the public folder.
- Every protected backend route verifies the Firebase ID token with the
  Admin SDK before touching any data, and every Firestore query is scoped to
  `users/{uid}`, so one user can never read or write another user's data.
- `firestore.rules` enforces the same isolation for any direct client-side
  Firestore access (profile creation, account deletion).
